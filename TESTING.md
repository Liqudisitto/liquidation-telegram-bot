# Проверки Liquidation 1.4.0

28 сентября 2026 года выполнены:

- **108** проверок мода и прежнего консольного моста, без пропусков. Лог в отдельном архиве мода: `tests/PLAYTIME_1_4_0_RESULTS.txt`.
- **16** проверок Python-бота. Лог в архиве бота: `tests/BOT_1_4_0_RESULTS.txt`.
- **6 отдельных сценариев** в открытом Java Kahlua: учёт/русский текст, права, клиент, версия, удобрения и новый удалённый мост. Подготовительные reset/stub-файлы не считаются отдельными сценариями. Лог: `tests/KAHLUA_1_4_0_RESULTS.txt`.
- Сквозной обмен настоящими строками протокола Lua → Python → Lua → Python: кириллица, дробный XP, изменение навыка, ответ, журнал с целочисленной датой, новый снимок. Скрипт: `tests/check_bot_wire.py`.

## Что проверяют новые тесты

Права Telegram и игрового клиента, запрет управления из групп, привязку кнопки к автору, отсутствие чтения данных неавторизованным пользователем; закрытое по умолчанию управление; повреждённые запросы; срок годности и смену загрузки/сессии/персонажа; повторное нажатие и перезапуск с уже записанной квитанцией; невозможность выполнить действие при ошибке записи журнала; отсутствие повторной отправки после тайм-аута POST.

Далее: отхил только после ответа нужного клиента; отсутствие ложного успеха без ответа; сохранность данных других модов и группы крови при очистке Wounds; запрет ранения отсутствующей кисти после ампутации плеча; повышение/понижение навыка без множителей; ожидание отложенного обновления XP без повторной выдачи; перенос дробного XP только с умершего того же аккаунта; отказ при отсутствующем навыке; чтение старой схемы с неизвестными навыками; сохранение новых снимков вместе с прежней историей.

В Kahlua дополнительно проверена совместимость обработки непустых таблиц без зависимости от `next`. Lua-файлы мода — ASCII; русские литералы используют UTF-8 escapes.

## Внешние исходники

Для сверки API и проверок фермерства использованы присланные пользователем Lua **Build 42.20.4**, **The Only Cure 2.4.0** и **Wounds Overhaul**. Хеши извлечённых файлов — `tests/SOURCE_HASHES_1_4_0.json`. Сами сторонние исходники и игровые архивы в выпуск не включены.

Это заменяет прежний снимок B42.20.2 для данного прогона. Из присланных файлов запускаются нужные функции фермерства на имитациях объектов; адаптеры здоровья и навыков проверяются на тестовых объектах и сопоставлены с исходниками и официальным API. Тесты не выдаются за исполнение всех сторонних модов в настоящем движке.

## Повторение

Для тестов мода нужен Python с `lupa`, внешний каталог `media/lua` игры и Linux для проверок бинарного консольного моста:

```bash
PZ_VANILLA_LUA=/path/to/media/lua PYTHONPATH=tests python3 -m unittest test_remote test_access test_playtime test_client test_b42_compat test_bridge test_fertilizer test_version -v
PYTHONPATH=tests python3 tests/check_bot_wire.py /path/to/extracted/bot
```

Тесты автоматически находят единственную игровую копию по VERSION.txt. Без внешнего ванильного Lua часть тестов фермерства будет пропущена; в указанном прогоне все выполнены. После распаковки в Linux исполняемый бит для `console/pz-watchdog` может потребоваться восстановить: `chmod +x console/pz-watchdog`.

Тесты бота из его каталога:

```bash
python3 -m unittest discover -s tests -v
```

Тесты не подключаются к Telegram, Steam, BotHost или серверу пользователя. Внешние библиотеки боту для запуска не нужны; Lupa требуется только для локальных тестов мода.

Для Kahlua: соберите открытый krka/kahlua2 и `tests/KahluaSmoke.java`. Передайте каталоги объединённых shared/server/client с Lua мода и внешними зависимостями фермерства, stdlib.lua Kahlua и пять `kahlua_*_smoke.lua` старых подсистем. Удалённый сценарий запускается отдельно после kahlua_smoke.lua, kahlua_remote_reset.lua и remote_stub.lua. Исходники и бинарники Kahlua в игровой мод не входят.

## Что ещё должно подтвердиться на живом сервере

Движок PZ **42.20.4**, настоящие Java-объекты, передача здоровья/XP по сети, поведение клиента после ампутации и конкретный API EGNetwork не запускались здесь. Бот не публиковался в GitHub и не разворачивался в аккаунте BotHost. Локальные тесты не доказывают совместимость со всеми остальными модами сборки.

Первый запуск: сравнить карточку и время с игрой; на тестовом персонаже проверить +1/−1 уровень, переподключение и сохранение XP; затем смерть и перенос на новый персонаж; отдельно рану/отхил и ампутацию. Это проверка фактической интеграции, а не повторение локальных тестов.

Если бот сообщает частичный/неизвестный результат, проверь состояние в игре и запись запроса: отсутствие ответа не означает отсутствие изменения. В текущем выпуске нет автоматического отката нескольких уже применённых навыков при исключении движка в середине операции.
