# GeniusMobilus

**Управление сервером Project Zomboid и персонажами через Telegram бота.**

Версия: **1.5.0.6.9** · Python: **3.11** · Версия игры: **Build 42.20.x**

Бот показывает историю персонажей, время игры, навыки, убийства зомби и обстоятельства смерти. Гений (администратор) может лечить персонажей, наносить раны, менять навыки, переносить их после смерти, управлять ампутациями поддерживаемых модов и запускать, останавливать или перезапускать игровой сервер.

Интерфейс и отчёты — на **русском языке**. Управление работает в личном чате с ботом через кнопки и некоторые команды.

## Возможности

### Статистика игроков и персонажей

- **Список игроков онлайн** и всех игроков, записанных модом.
- **Отдельная карточка каждого персонажа** с именем, серверным логином и уникальным номером записи. Персонажи с одинаковыми именами не объединяются в одну запись.
- **Общее реальное время игры и время за сегодня**: суммарно по аккаунту и отдельно по персонажам.
- **Статус персонажа**: жив или мёртв; наличие на сервере на момент последнего снимка.
- **Рождение и смерть** в двух шкалах: **игровая дата и время** и **реальная дата и время**. У живого персонажа отображается дата отчёта.
- **Сохранённые уровни навыков и накопленный XP**, включая силу, физподготовку и доступные зарегистрированные навыки модов.
- **Число убитых зомби**.
- **Список отсутствующих частей конечностей** при активном The Only Cure или Casualties Undead.
- **Просмотр сохранённой истории офлайн-персонажей**. При устаревших данных бот показывает соответствующее предупреждение.

Время игры считается по реальному времени нахождения в игре, а не по скорости игровых суток. Это не счётчик активности: отдельно исключать AFK бот не умеет. По умолчанию граница дня и реальные даты используют **UTC+03:00, Москва**. Часовой пояс берётся из настроек игрового мода; изменение часового пояса VPS само по себе не изменит отчёт.

Учёт начинается после установки и запуска мода. Прошлые часы не восстанавливаются автоматически. У персонажа, существовавшего до установки, дата рождения может быть неизвестна. **Подключение бота и установка мода сами по себе не сбрасывают навыки персонажей.**

### Управление персонажем

Изменения доступны для текущего живого персонажа, находящегося на сервере. Перед действием бот показывает игрока, персонажа и параметры и запрашивает подтверждение.

| Действие | Что делает |
| --- | --- |
| **Полный отхил** | Лечит раны и инфекцию. Ампутации сохраняются. |
| **Убить** | Убивает выбранного персонажа. |
| **Укус** | Добавляет укус на выбранную доступную часть тела. |
| **Царапина** | Добавляет царапину на выбранную доступную часть тела. |
| **Рваная рана** | Добавляет рваную рану на выбранную доступную часть тела. |
| **Глубокая рана** | Добавляет глубокую рану на выбранную доступную часть тела. |
| **Изменение навыка** | Устанавливает выбранный уровень от 0 до 10; можно повышать и понижать. |
| **Перенос навыков умершего** | Заменяет навыки нового персонажа сохранёнными навыками умершего персонажа того же аккаунта. |
| **Ампутация¹** | Удаляет выбранную часть конечность. |
| **Вернуть конечность¹** | Восстанавливает отсутствующую конечность. |

*¹ Доступны только через моды The Only Cure и Casualties Undead.*

Для ран доступны кисти, предплечья, плечи, верх и низ туловища, голова, шея, пах, бёдра, голени и стопы.

Отхил не воскрешает умершего персонажа. В Casualties Undead он также очищает поддерживаемые состояния болезней, кровопотери, органов и сердечного ритма. При этом не возвращает утраченные конечности или глаза и не стирает историю психических травм.

### Обстоятельства смерти

Если мод успел получить данные, карточка умершего персонажа содержит:

- **Причину смерти** либо предположение по последнему состоянию. Например, вирус Нокс, кровотечение.
- **Последние зарегистрированные раны** и части тела, на которых они находились.
- **Координаты смерти** X, Y, Z.
- **Город на стандартной карте**.
- **Время и источник снимка**.

Распознаются районы Малдро, Роузвуда, Риверсайда, Вест-Пойнта, Марч-Риджа, Луисвилла, Бранденбурга, Экрона, Эхо-Крика, Ирвингтона, Фаллас-Лейк, Вэлли-Стейшн и аэропорта Луисвилла.

**Причина смерти не всегда может быть установлена точно.** Раны показывают последнее известное состояние, которое могло отличаться от состояния в сам момент смерти. Город определяется приблизительно по областям координат. Границы, загородные места и модовые карты могут определяются неизвестными.

### Управление сервером

В главном меню есть раздел **«Управление сервером»**.

| Кнопка | Результат |
| --- | --- |
| **Сохранение мира** | Отправляет в консоль команду `save`. Завершение сохранения проверяется по консоли сервера. |
| **Проверка апдейтов** | Отправляет в консоль команду `checkModsNeedUpdate`, читает новый ответ из консоли и показывает в Telegram. |
| **Перезапуск сервера** | Ну тут всё понятно. |
| **Выключение сервера** | Как и здесь. |
| **Включение сервера** | В целом тут тоже. |
| **Обновить состояние** | Запрашивает состояние процесса у панели. |

Проверка апдейтов относится к **модам Steam Workshop**, а не к версии Project Zomboid. Ответ `Mods updated` означает **«моды актуальны»**. При `Mods need update` бот сообщает о найденных обновлениях. При `Check not completed` бот сообщает о потере связи с консолью.

**Бот не скачивает моды** этой кнопкой и сам не перезапускает сервер по результату проверки.

## Совместимость

Бот и мод Liquidus [B69] должны быть одной версии — **1.5.0.6.9** (30.09.2026). Базовая статистика, навыки, отхил, убийство, выдача укуса, глубокой раны, рваной раны, царапины работают без модов.

|  | Поддержка в этой версии |
| --- | --- |
| Project Zomboid | Версия **42.20.x**. Совместимость с Build 41 аннигилирована. |
| Liquidation [B69] | Обязательный мод на сервере и клиентах. |
| The Only Cure | Состояние, ампутация и восстановление частей рук. |
| Casualties Undead | Состояние, ампутация и восстановление рук и ног, доп. состояния при лечении. |
| Wounds Overhaul | Очистка модовых медицинских состояний (сепсис, кровопотеря) при лечении и их учёт при смерти. |
| Pterodactyl | Нужен совместимый Client API для файлов, состояния, команд, питания сервера и WebSocket-консоли. |
| Python | Версия **3.11**. |

Мод определяет активные медицинские моды, а бот показывает доступные функции по присланным возможностям. При отсутствующем или неготовом адаптере управление конечностями не предлагается. После обновления стороннего мода его API может измениться, поэтому поддержка перечисленных версий не означает совместимость с любой будущей версией.

**Casualties Undead и The Only Cure нельзя включать одновременно.** В Casualties Undead не предусмотрена поддержка The Only Cure (Оно и понятно почему). При обнаружении обоих управление конечностями блочится.

## Установка

Нужны сервер с панелью **Pterodactyl и доступным Client API**, мод **Liquidus [B69] 1.5.0.6.9** и место для запуска бота.

### Шаг 1. Установите мод

Добавьте [Liquidus](https://steamcommunity.com/sharedfiles/filedetails/?id=3809252806) на сервер. При вводе команды `/liquidusversion` в игре менюшка должна показывать **1.5.0.6.9** у сервера и клиента.

### Шаг 2. Получите два ключа

- В [@BotFather](https://t.me/BotFather) создайте бота и получите **его Telegram токен**.
- В аккаунте панели игрового сервера найдите настройку **API / API Credentials** (может варьироваться) и создайте **API-ключ**. API-ключ нужен, чтобы выдать ТГ боту права на чтение и запись файлов, состояние сервера, команды и WebSocket-консоль, запуск, остановку и перезапуск.

### Шаг 3. Создайте бота на BotHost

*Другими хостингами не пользовался.*

Используйте этот репозиторий или его копию. Файлы бота должны лежать в корне репозитория.

На [BotHost](https://bothost.ru/) создайте Telegram-бота (стоит денег, 99 ₽): напишите имя, укажите **Git URL репозитория**, версию **Python 3.11**, ветку `main.py` и токен от BotFather.

### Шаг 4. Задайте переменные бота

В настройках бота в разделе **«Переменные»** на BotHost укажите:

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен от BotFather |
| `ADMIN_IDS` | Ваш Telegram ID (Чек Шаг 5. Пока оставьте поле пустым) |
| `PZ_PANEL_URL` | Ссыль панели, например `https://panel.example.com` |
| `PZ_SERVER_ID` | ID из адреса страницы сервера. К примеру, для `https://panel.example.com/server/253r5643` это `253r5643` |
| `PZ_API_KEY` | API-ключ (который создали в аккаунте панели игрового сервера) |
| `PZ_CACHE_LUA` | `/.cache/Lua` |
| `PZ_PREFIX` | `LiquidusPlaytime_Liquidus_` |

### Шаг 5. Разрешите себе доступ

1. Запустите бота, напишите ему в личку `/myid`.
2. Полученный ID впишите в `ADMIN_IDS` на BotHost и перезапустите бота.
3. На игровом сервере, в папке из `PZ_CACHE_LUA`, создайте файл `LiquidusPlaytime_Liquidus_remote_admins.txt` и впишите туда ваш Telegram ID.
4. Сохраните файл. Для нескольких гениев (администраторов): в `ADMIN_IDS` — ID через запятую, в файле — **по одному** на строку.

Доступ нужен в **обоих местах**. Гений из `ADMIN_IDS` видит статистику всех игроков, а серверный файл дополнительно разрешает управление над игроками и сервером.

### Шаг 6. Проверьте

Войдите на игровой сервер, подождите несколько секунд и откройте в Telegram `/start` → **«Онлайн»** → своего персонажа. Если появились имя, время и навыки — подключение работает. В разделе **«Управление сервером»** проверьте состояние сервера.

## Команды и работа с меню

### Команды Telegram

Все команды используются **в личном чате**. Управление в группах закрыто.

| Команда | Назначение |
| --- | --- |
| `/start` | Открыть главное меню |
| `/menu` | Вернуться в главное меню |
| `/help` | Открыть меню с командами |
| `/myid` | Показать ваш Telegram ID |
| `/player "Имя пользователя"` | Открыть игрока и список его персонажей |
| `/stats "Имя пользователя"` | То же, что `/player` |
| `/totaltime "Имя пользователя"` | Общее время и сведения по персонажам |
| `/todaytime "Имя пользователя"` | Реальное время за сегодня только по персонажам, на которых сегодня играли |

Используйте **логин игрока на сервере**, а не имя его персонажа или Steam-профиль. Например, `/player "Liquid"`.

### Изменение навыков

Откройте персонажа → **«Навыки»** → нужный навык → уровень **0–10** → подтверждение.

Уровень устанавливается точно. Если у персонажа был уровень 5 и часть прогресса к 6, повторная установка уровня 5 уберёт этот прогресс между 2-мя лвлами.

### Перенос навыков после смерти

1. Игрок создаёт нового персонажа на **том же серверном логине** и входит на сервер.
2. Откройте нового персонажа → **«Перенести навыки умершего»**.
3. Выберите умершего персонажа-источник по имени и номеру записи.
4. Проверьте дату снимка навыков и подтвердите перенос.

Переносятся сохранённые уровни и XP записанных навыков, включая силу и физподготовку. Это **замена, а не сложение**: более высокие навыки нового персонажа тоже могут понизиться. Перенос не удваивает XP при повторном применении.

Не переносятся профессия, черты, рецепты, прочитанные книги, инвентарь, состояние тела, убийства зомби и время игры. История умершего сохраняется. Если снимок навыков не был записан, получить его задним числом нельзя. Отсутствующий в текущем модпаке навык или изменившаяся таблица XP могут заблокировать перенос.

## Данные и обновление

### Где хранятся данные

История хранится на **игровом сервере**, в разделе `cachedir/Lua`. При стандартном префиксе используются, в частности:

| Файл или группа | Назначение |
| --- | --- |
| `LiquidusPlaytime_Liquidus_state_a.txt`, `..._state_b.txt` | Основное состояние учёта |
| `LiquidusPlaytime_Liquidus_ГГГГ-ММ-ДД.txt` | Отчёты по реальным датам |
| `LiquidusPlaytime_Liquidus_characters.txt` | История персонажей |
| `LiquidusPlaytime_Liquidus_remote_snapshot_a.txt`, `..._b.txt` | Снимки данных для Telegram бота |
| `LiquidusPlaytime_Liquidus_remote_admins.txt` | Список разрешённых Telegram ID. Эдакий вайтлист. |
| `LiquidusPlaytime_Liquidus_remote_journal.txt` | История операций над персонажами |
| `LiquidusPlaytime_Liquidus_remote_request.txt`, `..._response.txt` | Обмен запросами и результатами |

**Не редактируйте состояние, снимки, журнал и служебные запросы вручную.**

Снимки для бота обновляются примерно раз в пять секунд при работающем моде. При выключенной игре можно читать последние доступные записи, но актуальный онлайн и изменение персонажей недоступны. После аварийного выключения сервера последние события могут не успеть записаться.

### Обновление бота

1. Остановите бота.
2. На Bothost.ru в разделе **«Мои боты»** выберите связанного с сервером и рядом с кнопкой запуска должна быть кнопка **«Обновить из Git»**. Нажмите на неё.
3. Подождите обновления. Перезапустите бота. Готово!

## Факи

| Трабл | Решение (возможное) |
| --- | --- |
| Бот не запускается, просит `BOT_TOKEN` | Токен должен быть в переменной окружения; при прямом запуске `.env` сам не читается. Откройте журнал запуска. |
| Бот отвечает «Доступ закрыт» | Получите `/myid`, добавьте ID в `ADMIN_IDS` и перезапустите бота с новыми настройками. |
| «Управление отключено» | Найдите `remote_admins.txt` с полным префиксом в правильном `Lua`; проверьте содержимое, UTF-8 без BOM и ошибки журнала мода. |
| Статистика есть, действие отклонено из-за прав | Конкретный ID должен быть и в `ADMIN_IDS`, и в серверном списке; права одного другого администратора не дают доступ всем. |
| HTTP 401/403 | Проверьте Client API-ключ, права его аккаунта, ограничения по IP и доступ к выбранному серверу. |
| HTTP 404 | Проверьте адрес панели, Server ID, `PZ_CACHE_LUA`, `PZ_PREFIX` и наличие файлов снимков. |
| HTTP 429 | Панель или Telegram ограничили частоту запросов; подождите и проверьте, что не работают лишние копии бота. |
| Игрок не найден | Используйте точный серверный логин с нужным регистром. Игрок должен хотя бы раз войти после установки мода. |
| Снимок устарел | Дождитесь загрузки мира; проверьте работу мода, запись файлов и корректное системное время на сервере и хостинге бота. |
| Не совпадают версии / нет клиентского адаптера | Обновите бот, серверную и клиентскую части Liquidation [B69]. Проверьте `/liquidusversion`, медицинские моды. |
| Нет кнопки ампутации | Нужен активный и готовый The Only Cure или Casualties Undead. В Ванилле она не предусмотрена. Wounds Overhaul сам по себе её не добавляет. |
| Конфликт CU и TOC | Оставьте включённым один мод ампутаций. Не пытайтесь решить конфликт переименованием Mod ID. |
| Клиент не ответил / итог неизвестен | Проверьте персонажа в игре, журнал операций, серверную и клиентскую консоль. Изменение могло примениться частично; не повторяйте вслепую. |
| `God Mode` блокирует действие | Выключите бессмертие у целевого персонажа перед нанесением урона. |
| `No module named 'workshop'` | Добавьте `workshop.py` той же версии рядом с `transport.py` и заново разверните код. |
| `No module named 'websocket'` / зависимость WebSocket недоступна | Установите **`websocket-client`** из `requirements.txt` и пересоберите окружение. |
| Проверка Workshop не даёт результата | Проверьте `websocket.connect`, `control.console`, доступность WSS и сертификат. Дождитесь загрузки игры; параллельная проверка другим администратором или watchdog может сделать результат неоднозначным. |
| Кнопка устарела после перезапуска | Отправьте `/menu` и выберите действие заново. Старые подтверждения не восстанавливаются. |
