# Liquidation Telegram Bot 1.4.0

Администрирование Liquidus на Project Zomboid 42.20.4. Python **3.11**, запуск `python main.py`. Нужен мод **LiquidusPlaytime 1.4.0** на игровом сервере и у игроков. Мод находится в отдельном архиве `Liquidation-1.4.0-FULL-UPDATE.zip`.

Бот показывает персонажей, время за сегодня и всего, навыки, убийства зомби и состояние конечностей. Кнопки позволяют вылечить или убить живого персонажа, нанести выбранную рану, выполнить ампутацию The Only Cure, изменить уровень навыка и перенести навыки умершего персонажа того же аккаунта. Все изменения требуют подтверждения в личном чате.

**Быстрый путь:** обновить мод → загрузить содержимое этого архива в GitHub → создать бота в BotHost → задать переменные → получить `/myid` → разрешить свой ID в боте и на игровом сервере.

## 1. Обновить игровой мод

1. Остановить игровой сервер, сохранить резервную копию `.cache/Lua`, `.cache/Saves` и текущей версии мода. Версия 1.4.0 читает старый учёт, но записывает новый формат LPT2. Возврат на 1.3.1 требует резервной копии состояния, сделанной до обновления.
2. По `00_START_HERE_RU.txt` из архива мода обновить существующую публикацию **3809252806**, сохранив **Mod ID LiquidusPlaytime**. В уже работающих строках `Mods=` и `WorkshopItems=` ничего переименовывать не нужно.
3. Дождаться обновления у сервера и игроков. Проверить `/liquidusversion`: все компоненты должны показывать **1.4.0**.
4. В консоли должна появиться строка `[LiquidusRemote] server=1.4.0; bridge=file-api; ...`. Через несколько секунд в `/home/container/.cache/Lua/` появятся файлы `LiquidusPlaytime_Liquidus_remote_snapshot_a.txt` и `..._b.txt`.

Этот бот не требует изменения Startup Command, SSH, открытого RCON или Python на EGNetwork. Он обращается к файловому API панели Pterodactyl по HTTPS; установленный Lua-мод обрабатывает запрос. Существующий watchdog можно оставить.

## 2. Подготовить Telegram-токен

В @BotFather создай бота через `/newbot` или используй своего существующего. Если токен уже был виден на скриншоте, выполни **`/revoke`**, выбери бота и используй новый токен. Вставляй его только в поле токена BotHost. В GitHub, исходники мода и Workshop токен не загружать.

Бот работает через long polling, вебхук и домен ему не нужны. Для одного токена запускай только один экземпляр этой программы.

## 3. Создать Git URL для BotHost

Готовый ZIP с кодом сам по себе не является Git-репозиторием. Репозиторий нужно создать в своём GitHub.

1. Открой https://github.com/new и войди в аккаунт.
2. Название, например: **liquidation-telegram-bot**. Для простого подключения без дополнительной Git-авторизации можно выбрать **Public**: в подготовленном коде нет твоих секретов. Не добавляй их впоследствии. Если используешь Private, подключи к BotHost доступ к этому репозиторию доступным в его интерфейсе способом.
3. Создай репозиторий. Для пустого репозитория нажми **uploading an existing file**; если уже есть README — **Add file → Upload files**.
4. Распакуй `Liquidation-Telegram-Bot-1.4.0.zip`. Загрузи **содержимое** распакованной папки. В корне GitHub должны лежать `main.py`, `bot.py`, `transport.py`, `protocol.py`, `ui.py`, `requirements.txt`, `bothost.json`. Не загружай ZIP одним файлом и не прячь код ещё на один уровень папок.
5. Нажми **Commit changes**. Посмотри имя ветки; в инструкции предполагается **main**.
6. Скопируй HTTPS-адрес через **Code → HTTPS**, например:

   ```text
   https://github.com/ТВОЙ_ЛОГИН/liquidation-telegram-bot.git
   ```

   Это шаблон: нужен адрес твоего реально созданного репозитория. Его и вставляй в поле **Git URL** на BotHost. Это не адрес Steam Workshop, панели EGNetwork или Telegram-бота.

В архиве нет опубликованного от твоего имени репозитория: публикацию выполняешь в своём аккаунте по этим шагам.

## 4. Создать бота в BotHost

На https://bothost.ru/ в форме создания:

| Поле | Значение |
| --- | --- |
| Язык / версия | **Python 3.11** |
| Git URL | Адрес своего репозитория из шага 3 |
| Ветка | **main**, если именно она создана |
| Основной файл | **main.py** |
| Токен Telegram | Новый токен от BotFather |

`bothost.json` уже указывает Python 3.11 и main.py. В репозитории также есть Dockerfile с тем же запуском для сборки через Docker; менять его не требуется. Сторонних Python-пакетов нет: пустой по зависимостям `requirements.txt` намеренный. Бот не требует отдельной базы данных или постоянного диска на BotHost: история хранится на игровом сервере.

Далее в **переменных окружения** задай:

| Переменная | Что вписать |
| --- | --- |
| `BOT_TOKEN` | BotHost создаёт её из поля токена; повторно задавать не нужно, если уже есть |
| `ADMIN_IDS` | Твой числовой Telegram ID, например `123456789`; несколько — через запятую |
| `PZ_PANEL_URL` | HTTPS-адрес именно панели EGNetwork, например `https://panel.example.com`; без `/server/...` |
| `PZ_SERVER_ID` | Идентификатор сервера из адреса страницы панели `/server/xxxxxxxx` |
| `PZ_API_KEY` | Клиентский API-ключ аккаунта панели EGNetwork с доступом к файлам этого сервера |
| `PZ_CACHE_LUA` | `/.cache/Lua` |
| `PZ_PREFIX` | `LiquidusPlaytime_Liquidus_` |

Примеры домена и ID здесь условные. Не используй IP игрового сервера с портом 25000 в качестве адреса панели. `PZ_SERVER_ID` — не Steam ID и не Workshop ID. Путь в `PZ_CACHE_LUA` считается от контейнера в файловом API; `/home/container` туда дописывать не нужно.

### Где взять API-ключ

В аккаунте панели EGNetwork открой раздел **API / API Credentials** и создай клиентский ключ для этого бота. Это ключ панели Pterodactyl, не Steam Web API и не SSH. Боту нужны чтение содержимого и запись файлов игрового сервера. Если аккаунт или отдельные права позволяют ограничить доступ только нужным сервером, используй такое ограничение.

Если API запрещён хостингом или в аккаунте нет этого раздела, отправь поддержке вопрос:

> Доступен ли Client API Pterodactyl для моего сервера: GET /api/client/servers/{identifier}/files/contents и POST /api/client/servers/{identifier}/files/write? Нужны чтение и запись TXT в /.cache/Lua из внешнего бота по HTTPS.

Не все панели дают ограничить ключ отдельной папкой. Считай ключ секретом с полномочиями своего аккаунта и храни его только в переменных BotHost. Адрес панели и ключ не требуется добавлять в игровой мод.

## 5. Узнать ID и включить доступ

Если не знаешь свой Telegram ID, оставь `ADMIN_IDS` пустым, запусти бота и напиши ему в личку:

```text
/myid
```

Команда покажет **твой числовой ID** даже до настройки связи с EGNetwork. Затем:

1. Запиши ID в `ADMIN_IDS` в BotHost и перезапусти бота.
2. Через файловый менеджер EGNetwork создай файл:

   ```text
   /home/container/.cache/Lua/LiquidusPlaytime_Liquidus_remote_admins.txt
   ```

3. Содержимое — тот же ID, по одному числу на строке, например:

   ```text
   123456789
   ```

   Для нескольких администраторов: в BotHost — числа через запятую, в этом файле — каждое с новой строки. Не добавляй кавычки, `@username`, `ADMIN_IDS=` или пробелы внутри ID. Сохрани UTF-8 **без BOM**. Пустые строки и комментарии с `#` допускаются.
4. Файл сервер перечитывает сам; перезапуск игры для изменения списка не нужен. Подожди около пяти секунд и открой в Telegram `/start` → **Онлайн**.

Без файла серверное управление выключено. Сбор статистики продолжает работать. Обычные игроки по-прежнему видят только свои игровые `/totaltime` и `/todaytime`; установка обновления не делает их администраторами бота.

Для отключения конкретного администратора убери его ID **из обоих мест** и перезапусти бота. Для запрета всех изменений очисти серверный файл. Доступ к чтению статистики в Telegram задаётся `ADMIN_IDS`; серверный файл дополнительно разрешает изменения персонажей.

## 6. Как пользоваться

Открой `/start`, выбери игрока и персонажа. Офлайн-история доступна для просмотра; менять можно только текущего живого персонажа онлайн. Все управляющие кнопки ведут к экрану подтверждения, где указаны логин, имя и уникальный номер персонажа.

Команды Telegram:

```text
/player "Имя пользователя"
/stats "Имя пользователя"
/totaltime "Имя пользователя"
/todaytime "Имя пользователя"
/myid
```

Используй серверный логин, регистр учитывается. У бота доступ только в личных сообщениях; управление в группах закрыто. В игровом чате прежние команды времени остаются без изменений.

### Изменение навыков

**Персонаж → Навыки → нужный навык → уровень 0–10 → Подтвердить**.

Можно повысить или понизить уровень. XP устанавливается на начало выбранного уровня: например, выбор 5 даёт ровно пятый уровень, без прежнего прогресса к шестому. Учитываются доступные зарегистрированные навыки игры и модов, в том числе сила и физподготовка.

### Перенос навыков после смерти

1. Игрок создаёт нового персонажа на **том же серверном логине** и входит на сервер.
2. В боте выбери **нового живого персонажа** → **Перенести навыки умершего**.
3. Выбери умершего персонажа-источник по имени и номеру записи.
4. Проверь данные и подтверди.

Переносятся сохранённые **уровни и накопленный XP всех записанных навыков**, включая силу и физподготовку. Это **замена**, не прибавление: более высокий навык нового персонажа тоже может понизиться. История умершего остаётся в учёте. Повторное осознанное применение снова установит тот же сохранённый набор; оно не удвоит XP.

Черты, профессия, рецепты, прочитанные книги, инвентарь, тело, убитые зомби и часы игры не переносятся. Старые персонажи, умершие до 1.4.0, не получат выдуманный снимок навыков. У живого старого персонажа навыки начнут записываться после входа с обновлением.

Снимок навыков обновляется примерно раз в пять секунд, дополнительно при регистрации, смерти и выходе. Если смерть пропущена из-за аварии, ручного удаления персонажа или отключённого мода, запись может не получить статус «мёртв»: бот не угадывает смерть. Если мод с навыком удалён или изменил шкалу XP, перенос блокируется до изменения персонажа.

### Здоровье, раны, The Only Cure

- **Отхил** очищает ванильные раны/инфекцию, основные отрицательные показатели и состояние Wounds Overhaul из присланной версии. Учтено восстановление естественной регенерации. Изменения требуют ответа клиента игрока.
- Ампутированные конечности и протезы The Only Cure **сохраняются** при отхиле. Это не отрастание рук.
- **Укус / рваная рана / царапина**: выбери часть тела из меню. Используется обычная игровая механика повреждения; дальнейшее заражение зависит от настроек игры и модов.
- **Убить**: действие относится к выбранному живому персонажу и подтверждается только после того, как сервер видит смерть.
- В присланном **The Only Cure 2.4.0** доступны кисть, предплечье и плечо слева/справа. Ампутация выше по руке включает расположенные ниже части. Уже отсутствующие части не предлагаются. **Ампутации ног в этой версии мода нет.**
- Ампутация использует путь принудительной операции из админ-меню Only Cure, без хирургического урона, с заживлением культи. Это административное действие, не полноценная операция с предметами и timed action.
- Для укусов, ран, ампутации и убийства нужно отключить God Mode цели. Бот сообщит об отказе, если он включён.

Полный отхил не обещает сброс любых эффектов всех сторонних модов из сборки. Адаптеры написаны под присланные исходники Only Cure и Wounds Overhaul; для значительно изменившейся версии может понадобиться обновление адаптера.

## 7. Проверка после запуска

Начни с чтения: `/myid`, `/start`, карточка своего персонажа, сравнение `/todaytime` в игре и Telegram. Значения могут отличаться на секунды между запросами.

Первую проверку изменения навыка, смерти/переноса и здоровья проведи на тестовом персонаже с резервной копией: движок PZ и фактический доступ API EGNetwork не запускались в среде сборки. В `TESTING.md` перечислены выполненные локальные проверки и их границы.

Время и данные обновляются снимками; при остановке сервера последняя история остаётся читаемой, управляющие кнопки отключаются. Если ответ операции **«частично»** или **«результат неизвестен»**, сначала проверь игрока в игре и журнал бота. Не повторяй действие вслепую: часть изменений могла примениться. Один запрос не повторяется автоматически после сетевого тайм-аута.

Смена персонажа, переподключение или перезапуск сервера отменяют старое подтверждение. Открой карточку заново. После перезапуска бота старые кнопки также истекают.

## 8. Если не работает

| Признак | Что проверить |
| --- | --- |
| `/myid` не отвечает | Бот запущен в BotHost, токен новый и верный, с этим токеном нет второго процесса |
| «Доступ закрыт» | Числовой ID в `ADMIN_IDS`, перезапуск после изменения переменных |
| HTTP 401/403 | Ключ панели, доступ к серверу и права читать/записывать файлы |
| HTTP 404 | Домен панели, идентификатор из её URL, путь `/.cache/Lua`, префикс, наличие снимков |
| «Управление отключено» | `remote_admins.txt`, точное имя, ID, UTF-8 без BOM; ошибки `[LiquidusRemote]` |
| Статистика устарела | Сервер работает, версия 1.4.0 загружена, часы хостингов корректны, снимки обновляются |
| Клиент не подтвердил отхил | Игрок онлайн, мод 1.4.0 скачан и включён у него, ошибки Lua на клиенте |
| Нет умершего в списке переноса | Записана смерть; это тот же логин; есть снимок навыков после установки 1.4.0 |
| `journal=ERROR` | Сохрани копию `remote_journal.txt`, останови бот и сервер, разбери ошибку; не удаляй журнал во время работы ради повторения команды |

Для диагностики достаточно версии, кода ошибки, строк `[LiquidusRemote]` и ID запроса. Токен Telegram и ключ панели присылать не нужно.

## Файлы обмена и данные

В `.cache/Lua` используется префикс `LiquidusPlaytime_Liquidus_`:

- `state_a.txt`, `state_b.txt` — сохраняемая история времени, персонажей и снимков навыков;
- `remote_admins.txt` — разрешённые Telegram ID для изменения персонажей;
- `remote_snapshot_a.txt`, `remote_snapshot_b.txt` — снимки для чтения ботом;
- `remote_request.txt`, `remote_response.txt` — запрос и ответ;
- `remote_journal.txt` — последние 512 начатых операций и их результаты, защита от повторного выполнения.

Два снимка и контрольные суммы позволяют пережить чтение во время записи. Журнал записывается **до** изменения игрока. Это не криптографическая подпись: доступ к файлам защищается правами панели и HTTPS. Пользователь с правом произвольно менять серверные файлы уже обладает административным доступом к этому мосту.

Для работы бота не нужны файлы с паролями игроков, Steam-авторизация или база аккаунтов PZ. В публичный GitHub/Workshop не включать `.cache`, сохранения, снимки статистики, `remote_admins.txt` или ключи.
