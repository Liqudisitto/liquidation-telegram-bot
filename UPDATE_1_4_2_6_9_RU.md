# Liquidation 1.4.2.6.9

Собрано из присланных исправленных архивов 1.4.1 FIX. Обновляются две части: мод на сервере и у игроков, а также Telegram-бот. Workshop ID **3809252806**, Mod ID **LiquidusPlaytime** остаются прежними.

## Что добавлено

- В карточке любого персонажа, в том числе умершего, есть **Главное меню**.
- В главном меню есть **Ликвидус**: **Сохранение мира**, **Проверка апдейтов**, **Перезапуск Ликвидуса**, **Выключение Ликвидуса**, **Включение Ликвидуса**.
- Включение работает через панель EGNetwork даже при выключенной игре. Состояние панели и кнопка обновления доступны в этом же разделе. Переходы и результаты меняют прежнее сообщение бота.
- Для новых смертей сохраняются последние раны с частями тела, координаты и, где можно определить, район города. Обстоятельства видны в Telegram-карточке, /totaltime и серверном журнале characters.txt. /todaytime сохраняет прежний краткий формат без дат.
- Добавлена оценка причины смерти: Нокс-вирус, кровотечение, тяжёлая кровопотеря и сепсис Wounds Overhaul, огонь/ожоги. Вывод из состояния отмечается **предположительно**; несколько подходящих признаков перечисляются вместе. Если оснований нет — **не установлена**. Для убийства через этот бот записывается отдельная подтверждённая причина.
- Исправлен обход таблиц при удалении отключившихся игроков и устаревших запросов: совместимость с итераторами Kahlua.

## Как обновить

1. Штатно останови сервер. Сохрани резервные копии `/home/container/.cache/Lua`, сохранения мира и текущей версии мода. Учёт переходит на формат **LPT3**: старые LPT1/LPT2 читаются автоматически с сохранением времени, персонажей и навыков. Для отката на 1.4.1 нужна копия файлов учёта, сделанная до обновления.
2. Из **Liquidation-1.4.2.6.9-WORKSHOP.zip** возьми папку **Liquidation_Update_1_4_2_6_9** целиком. Помести её в `%UserProfile%\Zomboid\Workshop\` на компьютере, с которого публикуешь мод.
3. В загрузчике Workshop в игре выбери именно эту папку и обнови существующий предмет **3809252806**. В `workshop.txt` уже сохранён этот ID. Можно сохранить своё описание и видимость, оставив ID прежним. Новый предмет Workshop создавать не нужно.
4. Обнови мод на игровом сервере и всех клиентах. Если осталась старая ручная копия `LiquidusPlaytime`, убери её из пути загрузки модов, чтобы игра не выбрала прежний код. **Файлы статистики в `.cache/Lua` и мир оставь на месте.** В `Mods` и `WorkshopItems` ничего переименовывать не нужно.
5. Из **Liquidation-Telegram-Bot-1.4.2.6.9.zip** загрузи содержимое в существующий GitHub-репозиторий бота с заменой файлов. `main.py`, `bot.py`, `transport.py`, `protocol.py`, `ui.py`, `bothost.json` должны лежать в корне репозитория. Выполни Commit changes.
6. В BotHost обнови/пересобери приложение из этой ветки и перезапусти бот. Python **3.11**, основной файл **main.py**. Существующие переменные окружения сохраняются. Токен и ключ API в GitHub не добавляются.
7. Запусти сервер и игру. `/liquidusversion` должен показать **1.4.2.6.9** для клиента, общих файлов, сервера и удобрений. В BotHost должна быть строка `Liquidation bot 1.4.2.6.9 started`. В Telegram открой `/menu`.

SSH, Startup Command и установленный watchdog 1.4.1 для этого обновления менять не нужно. В этих архивах нет замены watchdog.

## Доступ к разделу «Ликвидус»

Используются прежние настройки:

```text
PZ_PANEL_URL=https://gcp.egnetwork.ru
PZ_SERVER_ID=298a9290
PZ_CACHE_LUA=/.cache/Lua
PZ_PREFIX=LiquidusPlaytime_Liquidus_
```

`PZ_API_KEY` — действующий клиентский ключ панели. Учётной записи ключа нужны доступ к серверу, чтение/запись файлов, отправка команд в консоль и обычные действия Start / Stop / Restart. При HTTP 401/403 проверь эти права в EGNetwork; API зависит от возможностей хостинга.

Твой Telegram ID должен быть и в `ADMIN_IDS` BotHost, и в:

```text
/home/container/.cache/Lua/LiquidusPlaytime_Liquidus_remote_admins.txt
```

Один ID на строке, UTF-8 без BOM. Разрешение перечитывается перед действием даже при выключенной игре. Если файл недоступен, команда не отправляется. Для включения сервер должен быть выключен, для остальных действий — запущен. Во время Starting/Stopping новые операции блокируются.

| Кнопка | Действие |
| --- | --- |
| Сохранение мира | В консоль передаётся `save`. Завершение сохранения видно в консоли игры. |
| Проверка апдейтов | В консоль передаётся `checkModsNeedUpdate`; результат приходит в игровой чат и консоль. Проверяются моды Workshop, не новая версия PZ. |
| Перезапуск Ликвидуса | Обычный Restart панели после подтверждения. Ручной перезапуск начинается сразу, без пяти минут ожидания watchdog. |
| Выключение Ликвидуса | Обычный Stop панели, без принудительного Kill. Штатная процедура сохранения/остановки определяется командой остановки хостинга. |
| Включение Ликвидуса | Start панели. Бот не зависит от работающего Lua-мода для этого действия. |

Панель подтверждает принятие запроса, а не окончание сохранения или загрузки мира. «Запущен» — состояние процесса в панели; тяжёлый мир может ещё загружаться. Используй **Обновить состояние** и консоль сервера. Если сеть оборвалась после отправки, бот покажет неизвестный результат и не повторит действие автоматически.

Ручная проверка Workshop не меняет состояние watchdog и не запускает его отсчёт сама по себе: автоматические проверки и перезапуски остаются по прежнему расписанию watchdog. В журнале операций бота по-прежнему отображаются действия с персонажами; команды панели записываются средствами самой панели от владельца API-ключа.

## Как записывается смерть

Клиент отправляет ограниченный снимок своего здоровья примерно раз в две реальные секунды и отдельный снимок при смерти. Сервер связывает его с текущим персонажем отправителя, проверяет факт смерти сам и записывает координаты по своему объекту игрока. Даты рождения/смерти остаются в двух строках — игровые и реальные. Время игры остаётся только реальным.

Записываются укус, царапина, рваная и глубокая раны, кровотечение, ожог, перелом, пуля, стекло, инфекция раны, повязки и швы с названиями частей тела. Данные о ранах — последние полученные наблюдения, а не гарантированно точное вскрытие: при разрыве соединения последняя рана может не успеть передаться. В карточке указаны источник и время получения снимка; старый или неполный снимок помечается явно. Инфекция обычной раны не считается Нокс-вирусом.

Причина определяется по признакам тяжёлого состояния, а не по каждому событию урона движка. Падение, удар машины, конкретный нападавший, произвольные болезни других модов и одновременные источники урона могут не определиться. Полученные данные от клиента используются только для отчёта, не дают прав на управление и не устанавливают время игры.

Города определяются по областям стандартных бумажных карт: **Малдро, Роузвуд, Риверсайд, Вест-Пойнт, Марч-Ридж, Луисвилл**. Это приблизительное определение района, а не официальная граница города. Новые области B42, модовые города, удалённые локации и интерьеры RV вне этих областей будут показаны как **город не определён**, с координатами, если сервер смог их получить.

Новые сведения собираются после установки 1.4.2.6.9. Для уже умерших персонажей причина, раны и место задним числом не выдумываются. Обновление не изменяет навыки, здоровье или ампутации существующих персонажей; прежние кнопки управления сохраняются.
